# Changelog

A release is a tag, `v` and the workspace version.
The starter template pins the release it was written against, and a game made from it moves to a newer one by changing that tag and reading here what moved.
Pushing a tag publishes its release page from its section here, through `scripts/release-notes.sh`.

## Unreleased

- The five tiles of `TileRegistry::standard()`, `void`, `wall`, `floor`, `door_closed` and `door_open`, are drawn in a standard look when the game's `TileAppearance` gives them none, filled by `TileAppearance::fill_standard` when a run's world comes up; a look the game set is never replaced.
  To change: nothing; a game that drew the standard tiles only to see them may drop those looks.

- `commands.spawn_player(map, bundle)` spawns the player into a place: an actor that blocks, with the game's bundle, warped to the place's entry once the spawn is applied.
  To change: nothing; a start may replace its spawn at `Point::ZERO` and its `WarpRequest::into_place`.

- `app.places(rules)` hands the engine a game's place rules once, where the game is put together, and says the game needs a `Seed`; a run whose start makes no `WorldMap` gets one built over `PlaceRules::tiles`, and a start that makes its own keeps it.
  To change: nothing; a start may drop its `insert_resource(WorldMap::new(..))` and its `PlaceRulesRes`, and add `places(rules)` where the game adds its plugins.

- `PlaceRules::build` takes the place's `PlaceSeed`, derived from the run's `Seed` and the map's number alone, and `PlaceRules::tiles` names the tile tables places are built of; `MapId::FIRST` is map one. A warp into a place not yet built, in a game with no `Seed`, builds nothing and fails naming the missing seed.
  To change: add `seed: PlaceSeed` to `build` and run the chain on it in place of a seed kept in the rules or mixed with the depth by hand; add `fn tiles(&self) -> TileTables { self.tiles.tables() }`.

- `PlaceSeed`, one seed per place derived from the run's seed and the place's number, and `Chain::run` and `Chain::run_retrying` take it or a `RunSeed`.
  To change: nothing.

- `light_tiles` moved from `rl_render::looks` to `rl_rules::tiles`, so a game reads its tiles' light from its tiles file without a renderer; it reads only each line's `tile` and `light`, and `TileAppearance::load` still loads a line that writes a light and passes the light over.
  To change: `rl_render::looks::light_tiles` becomes `rl_rules::tiles::light_tiles` (`rl_engine::rl_rules::tiles::light_tiles` through the facade).

- The tutorial's steps, the template, Undermere and Foundry no longer set `EngineState::Playing` in their starts, their own or a continued run's, and leave it to the engine.
  To change: nothing; a game made from the template may delete the same line and the `NextState` parameter.

- Play begins on its own once a run's start, in `NewRun`, has built a `WorldMap` and no `HoldStart` holds it: `begin_run`, the door the first run, a title's New Game and every restart come through, sets `EngineState::Playing` in the frame a start used to set it.
  To change: nothing; a start may delete its `next.set(EngineState::Playing)` and the `NextState` parameter, and setting it by hand still works.

- The tutorial's binaries are numbered as the guide's chapters: `step07_content`, `step08_shove`, `step09_panels`.
  To change: a script that runs one by name uses the new name.

- The tutorial and the template no longer insert `DamageStages`, whose default is already `[SubtractArmor]`.
  To change: nothing; a game may delete the same line.

- `Reflects` carries the chance it turns a use back, `Reflects { percent }`, 50 by default, with `Reflects::ALWAYS` and `Reflects::NEVER` for a body that always or never does, and `Reflects::percent(n)` held to 100; a percent past 100 written into the field is read as 100. At the default a body rolls exactly as the unit `Reflects` did, so no run moves.
  To change: `insert(Reflects)` becomes `insert(Reflects::default())`.

- An actor tagged itself with what an offer needs (`Offering::needing`, or a container's `locked` key) now carries it, as one tagged with a lock's key always opened that lock: both ask `rl_rules::tag::carries`, its own tags or a thing it holds, where an offer used to look in the bag alone and refuse a warden a person or a chest would have let through the door beside them.
  To change: nothing, unless a game relied on a self-tagged actor being refused an offer; give such an actor a different tag.

- `NoiseRunning` and the stealth checks ask whether `NoisePlugin` and `StealthPlugin` were added by a marker only each plugin inserts, no longer by whether `NoiseHeard` or `Noticed` is registered, which the vitals and narration views register themselves; a game with those views and without stealth had its sleepers wait on a notice nothing rolls rather than waking on sight, and its vitals panel show a noise meter and a seen-or-hidden line that nothing would fill.
  To change: nothing.

- The sheet, the scrollback and the controls screen close on `CursorKeys::close`, the key every other screen closes on, so a game that rebinds it moves all of them; each had a close key of its own that the rebinding missed, leaving those three closing on Escape.
  The scrollback's bottom border now names its keys from `ScrollbackKeys` and `CursorKeys::close` unless `ScrollbackPanel::hints` set words of its own, and the controls screen's border names `CursorKeys::close`.
  To change: `SheetKeys::close`, `ScrollbackKeys::close` and `ControlsKeys::close` are gone; a game that set one sets `CursorKeys::close` instead (`app.world_mut().resource_mut::<CursorKeys>().close = KeyCode::KeyQ`), and drops the field from any `SheetKeys { .. }`, `ScrollbackKeys { .. }` or `ControlsKeys { .. }` it builds.
  A game that passed `ScrollbackPanel::hints` only to name a rebound key may drop the call.

- The inspect panel's health bar reads in the tone the vitals and nearby rails give the same health, bad at a quarter or less and worth noticing at half or less, where it was always the good tone.
  To change: nothing.

- Each desktop game saves in a directory of its own, `saves/<name>` beside the executable, named by its `SavePlugin` (`Saves::platform_default(name)`), so games built into one directory, as every example is in `target/debug`, no longer share one `settings.save.ron` and `records.save.ron` and wipe each other's settings. The first time a game runs with its directory, the run, settings and records an earlier build left directly beside the executable move into it, so a player who updates keeps them. The browser already kept each game under its own name and is unchanged. A slot is now a plain name, ASCII letters, digits, `-` and `_`: every backend refuses any other with the new `SaveError::Slot`, so no slot reaches outside the save directory, and `SavePlugin::new` and `Saves::platform_default` panic on a name that is not one, or, for `SavePlugin::new`, on `settings` or `records`, which the run would be written over.
  To change: a game whose `SavePlugin` name or own slots hold anything but letters, digits, `-` and `_` renames them; a `match` on `SaveError` adds a `Slot` arm. A tool or a player's guide that looks for saves beside the executable looks in `saves/<name>`.

- `BaseContext` holds no stream until one is installed, and a pass that draws from it before then panics, naming the fix, instead of drawing the same numbers every run from a placeholder seeded with 0; a `Chain` installs each pass's own stream as before.
  To change: a test or tool that applies a pass by hand, outside a `Chain`, hands its context a stream first with `set_rng(RunSeed(seed).rng(domain, index))`.

- The combat forecast reads a speed of 0 as 1, as the turn loop does, and charges each blow through `scaled_cost` as the loop does, so an actor at speed 0 is forecast the long fight it will fight rather than `u32::MAX` turns, and a duel whose count reaches `u32::MAX` no longer overflows while it reads the outlook (a panic in a debug build, a wrong outlook in a release one).
  To change: nothing.

- A shot, a throw, a bolt, a ball and a beam sent at a wall now all come to rest in the open cell in front of it, as a throw and a ball already did: `rl_grid::Footprint` gains `reached`, the farthest cell the flight got to and possibly the wall, and `landing` is now where it rests, never a wall, with a bolt's or a ball's `path` ending there rather than inside the wall; a bolt stopped by a wall beside its sender rests at their feet and covers nobody.
  `rl_bevy::shot`, `throwing::flight` and an ability's landing are one gathering over `footprint`, so the targeting preview of a shot no longer marks the wall where a throw marks the cell before it, and an effect placing something at `Landing::landed_at`, such as a teleport, finds open ground.
  To change: code that asks whether a flight got where it was aimed compares `reached`, not `landing`, with the aim (`landing` falls short of an aimed-at wall); a `Footprint` written as a literal or destructured whole names `reached`.

- `rl_engine::testing::let_time_pass(app, turns)` jumps the turn clock and every queued actor's due time by `turns` whole turns at once and runs one frame, so a test of what is written in elapsed time (a refill, a regeneration, an end at a reading) sees the span without playing it; no `TurnEnd` is sent and nobody is dealt a turn in it, so statuses, fields and minds stand as they were.
  To change: nothing; a game's tests may call it where only the clock is the question, in place of `pass_turns`.

- `examples/terminal`, a walk through generated rooms in a terminal that depends on `rl-core`, `rl-grid` and `rl-mapgen` alone and owns its loop with `crossterm`, with `terminal::{generate, step, look, render, direction_of}` as the tested rules and a `main.rs` that only maps keys to steps.
  To change: nothing.

- `rl_rules::ai::hearing::loudest`, `rl_rules::effects::landing_user` and `rl_grid::slide::slide` answer which of the sounds that reached one listener it goes to look for (the most left, a tie to the earlier cell in row-major order), who a landing is done by (the carrier when the thing is used as itself or answers as an actor, otherwise whoever used it, otherwise the carrier) and where a push or pull along a straight line ends (up to the distance, stopping before the first cell that is not free); the noise and effects systems had all three inline, and `EffectWorld::slide` keeps its signature as a gatherer over the same walk.
  To change: nothing.

- `rl_rules::trade::{each, quote, draw_down}` with `Deal`, `TradeRefusal` and `Piece`, and `rl_rules::prop::refusal` answer what one of a thing changes hands for (its worth bought, the trader's share sold), why a deal is refused (worn, then not bought, then no worth, then a short purse, the price saturating), which pieces a purse is drawn down by and how much of each, and why an offer is refused (a missing need before a short purse); `Refused` and `SpotRules` now live in `rl_rules::prop` and `Deal` and `TradeRefusal` in `rl_rules::trade`, and `rl-bevy` re-exports all four from the same paths, so `Trader::each` and `Trader::quote` keep their signatures.
  To change: nothing.

- `SpotRules` is no longer a Bevy `Resource`, since it lives in the Bevy-free `rl-rules`; the engine keeps it in a wrapper of its own that `PropsPlugin::spotting(rules)` sets.
  To change: a game that inserted or replaced `SpotRules` as a resource after setup passes it to `PropsPlugin::spotting` instead, and a system that read `Res<SpotRules>` stops, since there is no such resource to read.

- `rl_rules::equip::{gain, may_use, dark_sight}` answer how much better a wearer would be for putting a thing on (against what it displaces and, for a blow that would replace the wearer's own, against that blow), whether a thing may be used now (carried, not known empty, and worn when it is wearable) and the sight in the dark a wearer reads (the best of its own and what it wears, none while suppressed); the items systems had all three inline, and `rl_bevy::may_use` keeps its signature as a gatherer over the same rule.
  To change: nothing.

- `rl_rules::travel::followers` and `rl_grid::landing::landing` answer who travels behind whoever went through a way (those that follow, nearest first and a tie to the lower id) and where an arrival that takes up its cell stands (the wanted cell when free, otherwise the nearest free walkable cell by a breadth-first search capped at `reach` cells); the place systems had both inline.
  To change: nothing.

- `rl_rules::work::{break_reason, newly_sighted}` answer why work breaks off (death, then harm, then another worker finishing the target, then the target out of reach) and whether a foe is newly in sight; `BreakReason` now lives in `rl_rules::work` and `rl-bevy` re-exports it from the same paths, so nothing else moves.
  To change: nothing.

- `rl_rules::ai::awareness::{observe, unaware}` answer what one observer's turn with one subject leaves it knowing and whether that is news (the notice roll asked only of an unaware observer in view, an alert one in view kept without it, and an alert one out of view aging toward forgetting), and whether a watcher is unaware of a subject (a sleeper always, otherwise a hider at odds that nothing remembers); the stealth systems each decided these inline.
  To change: nothing.

- `rl_rules::status::{stumble, wakes_from_harm, side_change}` answer which way a stumbling holder is turned (the percent rolled first, then one open way picked, and nothing drawn for a holder walled in), whether a blow wakes the sleeper it lands on, and what side a status-turned holder moves to and keeps; the status systems each decided these inline.
  To change: nothing.

- `rl_rules::charges::{spend, recharge, periods, Spent}` answer what spending a charge leaves a thing as (charges still held, the next unit of a stack, gone, or empty and kept), how many charges a refill has earned and the progress it carries, and how many periods of a clock have run; the consumables' spend and recharge systems and the worn pulse each counted these themselves.
  To change: nothing.

- `rl_rules::ai::{step_as, StepAs, sort_roster, Trail}` and `rl_rules::ai::recent::Recent` answer what a mind's decision to step becomes (a swap with one who gives way, a door opened, a step, or a wait), who a mind sees sorted into enemies, allies and the others, which trail a search follows (the freshest offered, a tie to the lower cell) and the bounded cache the flow fields are kept in; the minds' system had its own copy of each.
  To change: nothing.

- `rl_rules::bump::{resolve_bump, classify_offers, BumpOutcome, Offered}` answer what walking into a cell comes to (a step, a door opened, a blow, a swap, the one plain thing offered taken up, or a question for a screen) and `rl_core::turn::step_cost` what a step onto a tile costs, a diagonal's 1.414 times; the bump redirect, the swap resolver and the step resolver each had their own copy and now ask one.
  To change: nothing.

- `rl_rules::arms::{choose_reach, first_charged, armor_total, mending_pct, scale_unaware, Reach}` answer which weapon an attack is made with (the blow beside the target, the shot down a clear line further off), the first worn weapon that has a charge, the armor a blow meets, how much of a heal arrives and what a blow on the unaware is worth; the resolver, the hit odds and the forecast's `Arms::at` each had their own copy of the weapon choice and now ask one.

- `rl_rules::damage::{apply_hit, heal, mitigate, Applied}` are what a hit and a heal do to health: a hit's new health with what it dealt, what was lost and whether it died, a heal scaled by mending and stopped at the most, and what lands after an invulnerable target or a peaceful place; `apply_damage` and `apply_healing` ask them.

- `rl_rules::faction::stance(factions, a, b)` is the one answer to how one side regards another, `None` when there is no faction table or either side takes none; the seven copies of it in stealth, bumping, the minds, work, props and sleep each kept their own fallback and now ask it.

Foundry's rangefinder helmet and its probes' radar, and Undermere's lent traits, moved onto them; neither fingerprint moved.

A game that kept a wearer's dark sight from its gear with a system of its own puts `dark_sight` on the item's parts and its native sight in `ActorParts::dark_sight`, drops the system, and blinds with `DarkSightSuppressed`, ordering whatever puts that on before `ReactSet::Lend`; one that set `DarkSight` by hand on an actor that also wears dark sight writes its own as `OwnDarkSight`, or the worn thing's going takes it away. A game that held a status or lit a light while a thing is worn with a system of its own writes `holds` or `light_when: LightWhen::Worn`.
- What a status does to its holder can be written on the status, each field optional and absent meaning no mechanic. `StatusDef` gains `max`, the most instances a `Stack` status holds at once, a further one refused; `resists`, what its holder resists while it lasts, kept in `StatusResists` and added by `Loadout::resistances`; `side`, the faction its holder fights for while it lasts, with `SideWas` the side it goes back to, saved by the engine as `EntityState::side_was`; and `stumbles`, the percent of its holder's steps and bumps turned a random open way, in the new `DecideSet::Statuses` on the engine's `StumbleRng`, the run's seed needed only where a status stumbles. Built with `.at_most(n)`, `.resists(kind, pct)`, `.sides_with(faction)` and `.stumbles(pct)`, and written in a status file as `max`, `resists`, `side` and `stumbles`. `ActorParts::while_holding` is what a kind's stats do while it holds a status, put on as `WhileHolding` under the new `Source::Holding(status)`. The side, the resistances and the stat changes are kept in the new `ReactSet::Statuses`, after `ReactSet::Settle`. `NearbyPanel::statuses(key, asleep)`, or inserting `NearbyStatuses`, says on the rail what holds each actor, every badged status a facet under `key` and a sleeper doing `asleep`. A game that capped a stacking status, kept a status's resistance, side or stumble, or a kind's stats while it holds one, with a system of its own drops it for the field; one that saved the side a status turned a body from reads `SideWas`. A game that ordered its own reactions against what a status lends orders them against `ReactSet::Statuses`, and one with a status that stumbles inserts a `Seed`.

- Consumables through abilities: `Known` is rebuilt from what an actor carries as well as what it wears, a `Cost::Charge` on an item with no `Charges` spends the item whole (one off its stack, or the item itself), and `UseItem` on an item that `Grants` an ability becomes a `Use` of it in `ResolveSet::Redirect`, so a potion is a line of RON. `ItemRow` gains `lends`, and the bag describes an item by what it lends, opens the targeting cursor on an aimed one, and uses the rest on the spot. Corsair's rum grants its swig and `use_items` is gone.
- `TileAppearance::load`: tile looks from RON against the tile registry, every unknown, doubled or missing tile reported at once. The tutorial from chapter 8, Corsair and the delve read theirs from `assets/tiles.ron`.
- The save seam: `Saveable` and `SaveableState`, `AddSaveable::save_kind` and `save_state`, `RunSave` with `EntityState` and `KindSave`, `SavePlugin`, `SaveSlot`, `save_run`, `load_run` and `forget_save` in `rl-save`; `Quests` implements `SaveableState`. Corsair's save module is four kinds and four resources.
- `Health` is `current` and `max`; the field was `hp`.
- Noticing rolls for its subjects in spawn order, and `Snapshot::sort` breaks ties on identity, so neither depends on the order a query walks the archetypes in. `Snapshot::sort` needs `A: Ord`.
- `crates/rl-bevy/tests/fingerprint.rs`: a seeded run of minds, combat and stealth, hashed, as the tripwire for the determinism promise.
- Every actor has its own sight. `Mind` requires a `Viewshed`, sized by `Perception` and cast by the same `fov::cast` the player's is, recast in `DecideSet::Sense` when the mind holding the turn moved or the map's opacity changed (`Viewshed` gains `epoch`). `Sight`, noticing and `Watchers` read it; `perceivable`, the player-as-oracle, is gone, so monsters see round their own corners and fight where the player is not looking, and the "Give them `Perception(20)`" line in guide chapter 4 is true. Perception is a disc, as the player's sight is; Corsair's and the delve's `perception` values are raised by one for the corners a square had. Every replay recorded before this will not replay: the minds roll from `MindRng` and stealth from `StealthRng`, their own streams, rather than `CombatRng`, and the fingerprint is re-baselined.
- Minds without combat: `ActorView` carries `health: Option<Vitals>` and `faction: Option<FactionId>`, `hp_pct` returns `Option` and `is_hurt` is false for the unknown; `Snapshot::others` holds everyone neither friend nor foe, and `GiveWay { space }` steps off them. `MindsPlugin` no longer depends on `CombatPlugin`, registers `Attack` itself, and `StealthPlugin` reads `Option<Res<CombatRules>>`. `add_action` registers a sweeper once however many plugins call it.
- Flow fields toward any goal: `FlowFields` is keyed by goal cells, movement profile, doors and direction, built on demand and kept until the map's cost epoch changes. `TacticCtx` loses `approach` and `escape` for `fields: &mut dyn Fields`, with `step_toward` and `step_away_from`; `NoFields` for a test. `Hunt` walks toward every enemy it sees, `FleeWhenHurt` away from them, `SearchLastKnown` down a field to the remembered cell, and `Follow { keep_within, no_closer_than }` is a companion. A mind that has not noticed the player no longer needs a gate on the fields, since the fields point at what it sees.
- `Decision::Own(Box<dyn Choice>)` replaces `Decision::Game(u32)`: a mind's choice of a game's own action is a type, not a number. `Choice` in `rl-rules`, `Decision::own`, `MindChose::as_choice`, and `AddChoice::add_choice::<A>()` in `rl-bevy`, which registers the action and routes the choice to its intent. `Decision` is no longer `Copy` or `Clone`; `PartialEq` compares a choice by name. The tutorial's hog shoves.
- The perceive stage: `Thinking`, the snapshot of the mind holding the turn while it is filled, in `CorePlugin`; `DecideSet::Perceive` with `PerceiveSet::{Begin, Roster, Filter, Annotate}`, run only while a mind holds the turn; `Sight`, the one answer to what that mind can perceive; and one contributor per plugin (`perceive_roster`, `filter_unnoticed`, `perceive_belongings`, `perceive_abilities`, `perceive_fire`). `decide_minds` only sorts, decides and writes. `Snapshot` gains `senses` and `Sense`, a game's own knowledge pushed by type and read back with `sense::<T>()`, and loses `Clone` and `PartialEq`. `CameFrom`, required by `Mind`, fills `Snapshot::came_from`, and `Wander` no longer steps straight back while anything else is open. A mind no longer sees the dead of the same frame.
- Fixed: the first turn of a run could go to a monster spawned after the player, since new actors were queued in the order a query walked the archetypes. New actors are admitted with the player first and the rest in spawn order.

## 0.1.0

The first release.

- The engine's crates in four tiers: `rl-core`; `rl-grid`, `rl-mapgen`, `rl-world` and `rl-rules`, which never depend on Bevy; `rl-bevy`, `rl-render`, `rl-ui`, `rl-overworld` and `rl-save`; and `rl-engine`, the facade a game depends on.
- `RoguelikePlugins`, what every game adds, and a plugin per subsystem: combat, minds, statuses, items, abilities, lighting, stealth, streaming, facts.
- `Seed`, the one thing about randomness a game supplies; every subsystem derives its stream from it.
- `Registries`, every registry the engine reads, filled once; `Names` and `NameRef<T>`, so a game's own content names content and holds ids.
- `CombatRules::new(&sides).hostile(a, b)`, and `hunts` and `allied`.
- Panels as views, collectors and presenters, over `UiPlugin`, which owns the message log, with `add_tone` and `add_modal`.
- `templates/starter`, a game to generate with `cargo generate`.
- The guide in `docs/guide`, and three examples: the tutorial, the delve and Corsair.
